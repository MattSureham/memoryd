# memoryd × Obsidian 集成：设计与实现报告

> 这份报告面向所有读者，包括不写代码的人。它会先用日常比喻讲清楚系统为什么这么设计，再讲每一步具体怎么做，最后附上格式说明书和技术索引。

---

## 第一部分：先理解 memoryd 是个什么东西

### 一个银行金库的比喻

把 memoryd 想象成一家银行的**金库**，而不是一本摊开在桌上的账本：

- **金库（SQLite 数据库）**：所有记忆的"正本"都锁在这里。它有保安（加密）、监控（谁在什么时间改了什么）、门禁（不同工作区互相看不见）。任何一笔账的改动都要经过柜台，按规矩登记，不能直接冲进金库拿笔涂改。
- **柜台（运行时和协议）**：AI 助手每轮对话都要经过柜台。柜台先做"风险识别"（这笔业务最容易出什么错），再决定给它看哪些资料，看完资料才能回答问题，回答完还要登记"这次用了哪些证据"。
- **账本副本（Obsidian vault）**：你现在可以要一份**给人看的账本抄本**，放进 Obsidian 里随时翻阅。抄本可以拿回柜台说"我改了这里"，柜台会按正规流程把改动登记进金库。

这个分工是整套设计的核心：**正本永远在金库，抄本只是给人看、给人改的入口**。为什么不能让 Obsidian 直接当正本？因为 Obsidian 本质是一堆普通文本文件——没有锁、没有监控、没有门禁，谁（包括 Obsidian 的第三方插件、iCloud 同步）都能读改。把正本放那里，等于把金库的钱搬到咖啡桌上。

### 三条不可破坏的规矩

无论记忆从哪里来（对话、纠错、还是 Obsidian 笔记），都必须遵守：

1. **过安检**：所有内容进入金库前，先检查有没有密码、密钥之类的敏感信息，发现了就打码（脱敏），然后再上锁（加密）。
2. **有出生证明**：每条记忆都记得自己"从哪来"——是从哪次对话、哪个文件来的。这叫来源指针。你在 Obsidian 里写"Ruby 是猫"，系统记住的不只是这个事实，还有"它来自 vault 里 ruby.md 这个文件"。
3. **改错要走流程**：AI 从对话里"自学"到的行为规矩，必须攒够证据（至少 3 次纠错、横跨 2 个会话）并且**由人亲自批准**才生效。但**人亲手写的规矩**不受这个限制——你亲笔写的，当然算数。

## 第二部分：从 Obsidian 读入记忆（import）

运行一条命令：

```bash
memoryctl import-obsidian /path/to/你的vault
```

系统会按下面的流程工作。用**入境检查**来比喻：

### 第 1 步：清点行李（扫描）

系统递归翻遍 vault 里的每个 Markdown 文件，但会跳过隐藏目录（`.obsidian`、`.git` 这类）和"快捷方式"（符号链接），防止绕圈或读到不该读的地方。

### 第 2 步：比对指纹（幂等去重）

每个文件算一个"内容指纹"（SHA-256 哈希）。和上次导入的记录比对：

- **指纹没变** → 这个文件上次读过，直接跳过。所以你反复运行这条命令是安全的，不会产生重复记忆。
- **指纹变了或是新文件** → 进入下一步。

### 第 3 步：登记入境（SourceEvent）

文件全文（脱敏、加密后）作为一条"原始事件"存进金库。注意存的是**原文**，不是摘要——这是 memoryd 的核心信条："记忆要索引到原始经历，而不是压缩成事实。" 以后 AI 需要核对细节时，能回到这份原文。

### 第 4 步：识别特殊申报（frontmatter 派生）

如果你在笔记开头写了一段特殊格式的"申报单"（frontmatter），系统会额外派生一条结构化记忆：

```markdown
---
memoryd: fact
subject: Ruby
predicate: species
value: cat
---
Ruby 是一只猫，不是人。
```

三种申报类型：

| 类型 | 效果 | 类比 |
|---|---|---|
| `memoryd: fact` | 写入"世界记忆"：Ruby 的 species 是 cat | 在户籍系统登记一条事实 |
| `memoryd: policy` | 写入"策略记忆"：一条 AI 必须遵守的规矩 | 你亲笔签发的规定，直接生效 |
| `memoryd: episode` | 写入"经历记忆"：一段有标题、有人物的往事 | 装订进相册的一页 |

没有申报单的普通笔记也会入库（第 3 步），AI 检索时能找到原文，只是不会额外套用结构化格式。

两个贴心设计：

- **同一事实反复改**：fact 的身份由"主体 + 属性"决定（Ruby + species）。你把 value 从 cat 改成 dog，系统不会新建一条记忆，而是给同一条记忆记上"第 2 版"，旧版本保留在历史里。
- **`[[双链]]` 变成关系网**：Obsidian 里的 `[[六七]]` 写法会被识别为人物/实体，写进金库的实体关系图。以后 AI 回忆"六七"时，能顺藤摸瓜找到相关笔记。

### 第 5 步：注销离境记录（删除级联）

如果你**删除了**某个已经导入过的笔记文件，下次 import 时系统会发现"这个文件以前登记过，现在不见了"，于是执行**连锁注销**：删掉这条原始事件，连同从它派生的事实/策略/经历一起删除。出生证明制度在这里发挥作用——系统知道哪些记忆是这个文件"生"的。

> 注意一个不对称：删除**你写的**笔记会连锁删除记忆；但删除**系统导出给你的抄本**（见下一部分）不会删记忆——抄本只是抄本。

## 第三部分：把记忆导出到 Obsidian（export）

```bash
memoryctl export-obsidian /path/to/你的vault
```

系统把金库里的活动记忆"抄"到 vault 的 `memoryd/` 目录下：

```
你的vault/
└── memoryd/
    ├── world/       ← 世界记忆（事实）
    ├── policies/    ← 策略记忆（规矩）
    └── episodes/    ← 经历记忆（往事）
```

每个文件都是正常的 Obsidian 笔记，可以翻、可以搜，`[[实体]]` 写法还能让 Obsidian 的 Graph view 画出关系图。

### 防止"狗咬尾巴"：自激循环问题

导出后再导入，系统会不会把自己导出的文件又当成"新内容"读回去，无限循环？这是双向同步的经典陷阱。解法是**防伪标记**：

每个导出的文件开头都有：

```markdown
---
memoryd-managed: true
memoryd-hash: 3f8a2c...
---
```

`memoryd-hash` 是导出时正文的指纹。导入时：

- 文件有防伪标记，且正文指纹和标记一致 → "这是我自己的抄本，没人动过" → **跳过**。
- 文件有防伪标记，但指纹对不上了 → "有人改了我的抄本！" → 按正常流程把改动登记进金库。

于是形成一个优雅的闭环：**你在 Obsidian 里编辑导出的策略笔记，保存，跑一次 import，金库里那条策略就升到新版本**——Obsidian 成了 memoryd 的编辑器。

### 出口管制的两条规矩

1. **候选策略不导出**。AI 自学但还没被你批准的规矩，不会出现在 vault 里。它们只能走 `memoryctl inspect --all` + `memoryctl approve` 的正规审批渠道。这是为了防止"导出一圈再导回来"变相绕过人工批准。
2. **被遗忘的记忆会消失**。下次导出时，系统会清掉那些对应记录已被遗忘的抄本文件。

## 第四部分：一个完整的使用故事

1. 你在 Obsidian 建了一个 `人物/Ruby.md`，写上 frontmatter 申报"Ruby 是猫"。
2. 运行 `memoryctl import-obsidian`。金库里多了一条事实，出生证明指向这个文件。
3. 几天后 AI 在对话里提到"Ruby 上次……"，它检索到的正是这条事实，必要时还能调出你笔记的原文。
4. 你运行 `memoryctl export-obsidian`，vault 的 `memoryd/world/` 下出现了 Ruby 的抄本。你发现 `memoryd/policies/` 里有条策略"分析图片时只描述可见内容"，觉得不够严，改成"绝不推断画面外的事件"。
5. 再跑一次 import：系统发现抄本被真人改过，把策略升到第 2 版。下一轮对话起，AI 按新规矩办事。
6. 哪天你删掉了 `人物/Ruby.md` 并再次 import，这条事实连同它的历史一起从金库注销，仿佛 Ruby 从未被登记过。下次 export 时，`memoryd/world/` 里那份抄本也会被一并清走。

## 第五部分：必须知道的安全边界

| 事项 | 说明 |
|---|---|
| **vault 是明文** | 金库里的记忆是加密的，但导出到 vault 的抄本是普通文本。它会进入 Obsidian 自己的同步范围（iCloud、git、第三方插件），memoryd 管不到。敏感内容不要指望导出后还保密。 |
| **导入不是实时的** | 目前是手动命令，不是后台监控。文件保存后要再跑一次 import，AI 才能看到。 |
| **单文件出错不连坐** | 某个笔记格式写错了（比如 fact 缺了 value），只有这个文件被记入错误清单，其他文件照常导入。 |
| **敏感信息仍会打码** | 即使是 vault 来的内容，进金库前照样过脱敏安检。 |

## 第六部分：frontmatter 格式说明书（用户手册）

### 事实笔记

```markdown
---
memoryd: fact
subject: 主体（必填）
predicate: 属性名（必填）
value: 属性值（必填，文字/数字/真假）
scope: user 或 workspace（可选，默认 workspace）
confidence: 0 到 1（可选，默认 1）
---
正文随便写，是给人看的；[[实体]] 会被记入关系图。
```

### 策略笔记

```markdown
---
memoryd: policy
scope: user 或 workspace（可选，默认 workspace；不支持 session）
dependencies: [其他策略ID]（可选）
---
正文就是规矩本身，例如：分析图片时只描述可见内容。
```

策略的身份由文件路径决定：**原地编辑 = 同一策略的新版本**；移动文件 = 新策略（旧的还在，需用 `memoryctl revoke` 或 forget 处理）。

### 经历笔记

```markdown
---
memoryd: episode
title: 标题（可选，默认用文件名）
tags: [标签1, 标签2]（可选）
date: 2026-07-23（可选，默认用文件修改时间）
---
正文是这段经历的原文。[[出场人物]] 自动成为参与者。
```

## 第七部分：技术索引（给工程师）

| 内容 | 位置 |
|---|---|
| 适配器主体（解析、导入、导出） | `src/adapters/obsidian.ts` |
| CLI 命令 | `src/cli.ts`（`import-obsidian` / `export-obsidian`） |
| 测试（9 项：解析、派生、幂等、版本化、删除级联、错误隔离、导出跳过、编辑闭环、失效清理） | `tests/obsidian.test.ts` |
| 用户文档 | `README.md` "Obsidian vault 互通" 一节 |

关键实现决策：

- 导入的原文事件放在按 vault 路径决定的确定性 session（`obsidian-<哈希>`）里，因为系统的来源指针（SourceRef）强制要求 session；派生记录仍是 user/workspace 级，跨会话可见。
- 导入后调用 `rebuildDerivedIndexes` 刷新实体索引和向量索引；全文索引（FTS5）在写入时由存储层自动维护。
- 文件级幂等靠元数据里的内容指纹，事件级幂等靠存储层的 idempotency key，双保险。
- 删除检测不需要额外的状态文件：直接查询"上次从这个 vault 导入过哪些事件"，和当前文件列表对比即可。
