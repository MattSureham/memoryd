v0.1.0 · 协议 1.2 · 本地优先 · 开源 MVP

memoryd

跨 Agent 的本地长期记忆运行时
让 AI 不只"记住更多"，而是"越来越了解自己的认知边界"

01要解决的问题

长上下文不等于可靠的记忆。把整本"小说"塞进上下文，模型仍然会在关键时刻用错细节。

找到了，但找错了

检索到相似但错误的片段；最近的内容压过早期内容。

实体合并

多个人物、多个会话被错误地合并成一个——Ruby 被当成人，Andrew 被叫成 Michael。

叙事补全

模型根据"故事惯性"脑补画面外的事件，而不是读取眼前证据。

记住了事实，丢了语境

事实检索正确，但情绪、因果和叙事位置全部丢失。

"不要把记忆压缩成事实；要把记忆索引到原始经历。知识图谱负责找到门，原始对话片段才是门后的房间。"

因此 memoryd 的目标不是传统 RAG 的"从一堆笔记里找 top-k 段落"，而是：先识别这次最容易犯哪种错，再有节制地重建原始局部上下文。这是从"增加容量"到"提升元认知（metacognition）"的转变。

02核心流水线

每一轮对话都经过完整的"先担心、再检索、后回答、再学习"链路。

其中最关键的一个决策：记忆检索被放在模式控制之后，而不是之前。当系统判断"这里有叙事补全风险"时，会要求先独立观察画面、固化可见事实，然后才允许加载剧情记忆——专家不仅更早进入正确的思考模式，也知道哪些信息应该暂时隔离。

03三层记忆

三种记忆回答三个不同的问题，约束本身也是记忆。

Policy 像 CPU 缓存一样分层调度（L1/L2/L3/Archive）：最近频繁触发的规矩放最浅的检索层，长期未触发的降级到后台。但衰减的不是 Policy 本体，而是 Trigger 的激活频率——规矩永远有效，只是调度优先级随时间降低；条件再次出现时瞬间回到前台。

04安全的学习闭环

一次纠错不等于一条规则。系统只在聚类验证后、由人批准才改变行为。

事实纠错行为纠错
例子"Ruby 是猫""不要用剧情补全画面"
写入World Memory（直接生效）FailureCluster → Trigger 候选 / Calibration 影子模式
生效条件立即≥3 次独立纠错、跨 2 个会话、非实体特定，再由人 approve
影响范围单个实体所有未来的类似任务

学习到的校准模式先进入 shadow（影子）模式：在真实流量上只观察、不干预，累计样本与延迟指标，同时后台 worker 在历史对话上回放（replay）评估覆盖率和误激活率。全部指标达标才转为 active。这保证系统"越用越懂自己哪容易错"，又不会把偶然的口误固化成狭窄的规则——那是记答案，不是校准。

05运行结构

一个本地 sidecar，对接 Claude Code、Codex 与任意 Agent。

宿主持久化配置由 memoryctl install all --scope project 一条命令完成：写入 hooks、MCP 配置、Skills 和 AGENTS.md 指引。daemon 挂掉时 hooks 自动降级——允许 Agent 继续工作，失败事件进入加密队列稍后补写，绝不静默丢记忆。

memoryd

A local-first long-term memory runtime for AI agents
Not just "remember more" — know your own cognitive boundaries

01The Problem

A long context window is not reliable memory. Stuff the whole novel in, and the model still reactivates the wrong detail at the wrong moment.

Found, but wrong

Similar-but-incorrect passages win retrieval; recent content drowns out earlier context.

Entity merging

Multiple people and sessions get merged into one — Ruby the cat becomes a person; Andrew becomes Michael.

Narrative completion

The model infers off-screen events from story momentum instead of reading the evidence in front of it.

Facts without context

The fact is retrieved correctly, but the emotion, causality and narrative position are lost.

"Don't compress memory into facts; index memory into the original experience. The knowledge graph finds the door — the raw conversation episode is the room behind it."

So memoryd's goal is not classic RAG "top-k paragraphs from a pile of notes". It is: first predict which error is most likely here, then deliberately rebuild the original local context. This is a shift from adding capacity to improving metacognition.

02The Core Pipeline

Every turn runs the full loop: anticipate risk, gate retrieval, answer, then learn.

The single most important decision: memory retrieval runs after mode control, not before. When the system senses narrative-completion risk, it requires observing the image independently and locking visible facts before plot memory is allowed in. Experts don't just switch modes earlier — they know which information must stay temporarily isolated.

03Three Layers of Memory

Three kinds of memory answer three different questions. Constraints are memory too.

Policies are scheduled like a CPU cache (L1/L2/L3/Archive): recently triggered rules sit in the shallowest retrieval tier, long-dormant ones sink to the background. But what decays is the trigger's activation frequency, never the policy itself — the rule stays valid forever; only its scheduling priority fades, and it snaps back to the foreground the moment its condition reappears.

04A Safe Learning Loop

One correction is not one rule. Behavior changes only after clustering, replay — and human approval.

Fact correctionBehavior correction
Example"Ruby is a cat""Don't complete the scene from the plot"
Written toWorld Memory (immediate)FailureCluster → trigger candidate / calibration shadow
Takes effectImmediately≥3 independent corrections across 2 sessions, non-entity-specific, then human approve
Blast radiusOne entityAll future similar tasks

Learned calibration patterns start in shadow mode: they observe live traffic without acting on it, accumulating samples and latency metrics, while a background worker replays history to measure coverage and false-activation rates. Only patterns passing every metric turn active. The system gets better at knowing where it errs — without fossilizing one-off mistakes into narrow rules. That would be memorizing answers, not calibration.

05Deployment Shape

One local sidecar serving Claude Code, Codex, and any agent.

Host integration is one command — memoryctl install all --scope project — which writes hooks, MCP config, skills and AGENTS.md guidance. If the daemon is unreachable, hooks degrade gracefully: the agent keeps working, failed events land in an encrypted spool, and they replay later. Memory is never silently dropped.

06Tech Stack

Deliberately boring choices: zero cloud services, zero heavy dependencies, everything auditable.

Semantic search needs no external model service: the default embedding is a local deterministic feature hash. When an index is missing, retrieval degrades explicitly — re-weighting the remaining signals and recording it in the trace — instead of pretending semantic search happened.

08Getting Started

# Build and link (requires Node.js 22+ and pnpm 10)
pnpm install && pnpm build && pnpm link --global

# Start the local daemon and self-check
memoryctl start
memoryctl doctor

# Install agent adapters in a target project (Claude Code / Codex)
cd your-project
memoryctl install all --scope project

# Optional: connect an Obsidian vault
memoryctl import-obsidian /path/to/vault   # notes → memory
memoryctl export-obsidian /path/to/vault   # memory → notes
Security boundaries: the daemon listens on loopback only — no TLS, no multi-user isolation; notes exported to Obsidian are plaintext and enter the vault's own sync scope; losing ~/.memoryd/master.key makes encrypted payloads unrecoverable.
